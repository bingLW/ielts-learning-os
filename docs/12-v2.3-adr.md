# v2.3 架构决策记录（ADR）

## ADR-001 采用 L1 文件交换，不内嵌 TypeWords 引擎

- 状态：已采纳（2026-11-19）
- 背景：TypeWords 为 Nuxt 应用、GPL-3.0；OS 为 Next.js；两者存储为用户浏览器 IndexedDB。
- 决策：OS 只解析用户导出的备份包（ZIP/data.json），并生成可被 TypeWords 导入的兼容词库包；
  L2 浏览器桥接默认关闭，不跨域读写对方 IndexedDB。
- 理由：零运行时耦合、零 GPL 传染、可离线；代价是需要用户手动导出/导入，且只有汇总统计。
- 替代方案：内嵌练习组件（GPL 传染、构建体系冲突）；浏览器扩展桥接（隐私与稳定性风险）。

## ADR-002 词汇练习会话粒度固定为 SUMMARY_ONLY

- 状态：已采纳
- 背景：固定 commit 的备份没有逐词尝试日志，只有 `Statistics{total,new,review,wrong,spend,segments}`。
- 决策：导入的会话一律 `granularity='SUMMARY_ONLY'`，不生成 `VocabularyAttempt`，不推进七维掌握。
- 理由：伪造逐词尝试会污染证据链；汇总时长仍可计入学习时长（按区间去重）。
- 影响：七维掌握只能由 OS 内证据表单产生。

## ADR-003 词汇延迟复测独立于技能型复测

- 状态：已采纳
- 背景：`RetestSchedule` 已被 v2.2 技能复测使用，`ensureRetestChain` 对 `APPLIED_TASK/ASSISTED` 为 no-op。
- 决策：新增 `ensureVocabularyRetest()`，用 `note='VOCAB|<itemId>|<dimension>|<lemma>|'` 区分来源，
  幂等键 `vocab:<itemId>:<dimension>:DELAYED:<dueDate>`，间隔 [1,7,30] 天，仅 RECALLED 及以上排期。
- 理由：不改动既有技能复测行为；同词同维度新证据只结清已到期条目，未来排期保留。
- 验证：6 条单测 + e2e-v23 第 [5] 组 12 项断言。

## ADR-004 ZIP 解析使用 Web 标准 API，不新增依赖

- 状态：已采纳
- 背景：真实导出是 ZIP；引入 jszip 会增加体积与被替换风险。
- 决策：`readBackupArchiveText()` 读取中央目录，支持 store(0)/deflate(8)，
  解压用 `DecompressionStream('deflate-raw')`；纯文本原样返回。
- 限制：不支持 ZIP64/加密/其他压缩算法，超出时报可读错误并提示解压后选择 data.json。
- 验证：7 条单测（store、deflate、嵌套目录、纯文本、缺 data.json、截断包）。

## ADR-005 词条与词典幂等策略

- 状态：已采纳
- 背景：重复导入同一备份不应产生重复词条或时长。
- 决策：词条按 `normalizedLemma + pos + senseKey` 去重写入；会话按
  `provider + providerInstanceId + externalSessionId`（内容派生的 canonicalKey）幂等；
  时长先扣除与既有记录重叠的区间再入库。
- 验证：e2e-v23 第 [2]/[3] 组（首次导入 30 分钟、重跑 0 分钟、会话数不变）。
