## 3. 评分层（T04）

| 能力 | 状态 | 用户会看到什么 |
| --- | --- | --- |
| `errorRecurrence`（同类错误重复度） | **`0.00` 只在「该维度确实练过」时才等价于「没有重复错误」** | 若 28 天内该维度**一次都没练**，那是「没有观察」而不是「没有错误」。当前口径**仍返回 `0.00`**（错误重复度是**加重因子**而不是发现因子，未观察的维度应由 `PROBE` 补测路径接手，而不是靠这个因子被抬升），但 `/planner/candidates` 的决策轨迹会显式显示「近 28 天无记录（未观察）」而不是「0 次错误」。区分方式：`factorsJson.meta.noObservation` |

> 若后续能稳定拿到「该维度是否练过」的信号（`SkillGapSignal.evidenceQuestions > 0` 已可判），可把「未观察」升级为中性 `0.30`。这属于**口径变更**，必须递增 `weightsVersion`，否则历史决策不可复算。

### 3.1 `repeatedErrorCount`（错误重复次数）的口径

它是 `Mistake` 表近 28 天里**能归属到 `StudyRecord` 的错题条数**（技能从
`StudyRecord.skill` 取）。三点必须知道：

| 限制 | 后果 |
| --- | --- |
| `studyRecordId` 为空的错题不计入 | 手工录入、没挂学习记录的错题不会提高 `errorRecurrence`。宁可漏计也不错挂到某个技能上。**这是「按 `studyRecord.recordDate` 过滤窗口」的自然结果，不需要额外写一个 `studyRecordId: { not: null }`** —— 多写一个条件就多一处可以忘、也可以写错的地方 |
| 统计窗口按 `asOfDate` 回推 28 天，不是按「现在」 | 这是为了让同一 `asOfDate` 的快照永远可复算（否则同一输入在不同时刻算出不同 `inputHash`） |
| **窗口按错题「发生」的日期算，不是按「录入」的日期** | 这两个锚点会分叉：用录入时刻（`Mistake.createdAt`）的话，补录半年前的错题会让今天的 `repeatedErrorCount` 突然升高，而那些错题对历史 `asOfDate` 又永远不可见。所以锚点是 `StudyRecord.recordDate`（业务日期）。**补录不改变过去发生了什么，只改变「当时那些错确实存在」这件事被记录下来了** —— 只有按 `recordDate` 算，补录才会正确地落进它该落的窗口 |

## 4. 数据层遗留（**休眠风险**，不是当前缺陷）

这两条**今天不产生错误结果**，因为没有任何代码会触发它们；但将来谁加了相应功能就会撞上。所以按「休眠风险」记录，而不是按缺陷。

| 遗留 | 现状 | 触发条件（将来什么时候会疼） |
| --- | --- | --- |
| v2.5 语音域历史 SQLite DDL 的级联外键 | 历史迁移创建的语音域 DDL 不含 `ON DELETE` 子句；**当前 Prisma schema 已声明关系动作**（资产/练习/尝试/会话多为 `Cascade`，口语题引用为 `SetNull`）。两种库结构必须分别核对 | v2.7.1 资产删除只对无引用资产写 tombstone，不删除父资产或物理文件，因此不会触发级联；历史迁移库仍不能在应用层直接物理删除父行后假定没有孤儿，若新增该能力必须先验证并版本化迁移 DDL |
| `AIEngineSetting.id` 缺 DDL 级 `DEFAULT` | Prisma 上是 `@default("default")`，但 SQLite 里是 `"id" TEXT NOT NULL PRIMARY KEY`（无 `DEFAULT`）。Prisma 客户端插入时会补 `id`，所以应用侧无感 | 只有在**绕过 Prisma** 写裸 SQL / 数据修复脚本 / 手工 `INSERT` 时才会失败（`NOT NULL constraint failed`）。修它要重建表或加触发器，同样破纯加法边界，留 v2.8 |

> 判断「休眠风险」还是「缺陷」的判据：**有没有代码路径能触发它**。有 → 缺陷，本版修；没有 → 休眠风险，记录 + 等触发它的功能一起做。

## 11. v2.7.1 使用口径与发布边界

### 11.1 四种分钟数不得混用

| 口径 | 来源 | 用户会看到什么 |
| --- | --- | --- |
| 计划分钟 | 有效状态 `PlanTask.plannedMinutes` 之和，排除 `CANCELLED` / `DEFERRED` | Planner、Dashboard、预算页的「今日/本周计划时长」；不因实际超时自动改写 |
| 预算占用分钟 | `DONE` / `PARTIAL` 取 `max(0, actualMinutes)`；其他有效状态取 `max(actualMinutes, plannedMinutes)` | 只用于预算守卫、carryover 与冲突保护。`PARTIAL` 实际 15 分钟、原计划 10 分钟时占用 15，但已排计划仍显示 10 |
| 计时累计秒数 | 开始到暂停/当前时刻的活跃累计，包含暂停前的有效计时；不是净学习分钟 | 计时器用于继续计时与乐观锁，不直接充当分析看板的净时长 |
| 净学习分钟 | `StudySessionDaySplit.minutes`，先剔除误触/挂机，再跨零点拆分 | Dashboard、预算页与分析页的实际净时长；未计时的手工补录不进入该口径 |

趋势图至少需要 2 个非空有效点才绘制；只有 1 个点时显示「有效数据点不足」，不代表汇总值为 0 或没有记录。

### 11.2 尚未关闭的发布风险

- **真实库事故未关闭**：真实 `prisma/dev.db` 曾被误执行 `prisma db push`，文件 SHA-256 与 `schema_version` 均改变。没有误操作前的完整副本，不能声称逐字节恢复或真实库完全未受影响；后续对真实库禁止写命令。该风险未关闭前，P0-5 不得标 PASS。
- **浏览器验收范围**：本地 Chrome + Qoder Browser Connector 已验证隔离库上的诊断补测、报告取代、Planner 预览/确认、计时、预算、Dashboard、readiness、版本解释与分析页；并发双提交、DEMOTE 分支与 CYCLE 分支未执行，不得写成已通过。
- **Provider 真实 smoke**：默认 `NOT_RUN`；真实调用必须同时显式 opt-in、使用 `/tmp` 隔离库与合成数据。无凭据时不发外部请求，不把 NOT_RUN 写成 PASS。
- **无诊断的 DAY/WEEK 模板计划仍可用**：诊断提案本身保持 `DRAFT`，只有 Planner Confirm 才写正式任务；但通用 DAY/WEEK 生成不要求先有诊断。这是现状边界，不表示诊断报告已自动激活。
- **音频删除采用 tombstone**：只允许删除无引用的用户资产，数据库保留墓碑，物理文件刻意保留以避免误删历史；这不是级联物理删除。
- **周条带 `plannedMinutes` 命名遗留**：`queries/plan.ts` 的周条带字段来自预算占用分钟。v2.7.1 已修正 Planner Dashboard、总 Dashboard 与预算页的展示，但该旧 DTO 名称未改；消费前必须核对来源，不能按字段名猜口径。
