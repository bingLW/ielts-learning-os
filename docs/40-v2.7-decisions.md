### Q5 为什么否掉「B 保留原样」

1. `GATE_H4_MIN_MINUTES = 240` 要求「近 30 天有计划的日期中净时长 ≥240 分钟的占比 ≥80%」。按 v2.1 动态预算，**30 分钟/天与 60 分钟/天的用户永远无法满足**，晋级通道事实性关闭。
2. 与 v2.7 需求 §9「学习时长不能单独触发晋级」正面冲突；与约束 §7「不得恢复每天最低 240 分钟旧规则」正面冲突。
3. 审计报告 R-3 与 PM 的 C-1 独立指向同一处，不是误判。

### Q6 为什么不照抄 PRD 的「材料页改成跳转」

PRD 的 A 会**回退 v2.6 已验收的 UX**：用户在材料页手上有草案，却被要求跳到另一个页面确认。真正的问题不是「入口有两个」，而是**两个入口各自写库、覆盖字段不一致**（审计 R-2：材料路径落 `priority=P1`/`sourceKind=CORE`/`planVersion=1`/`splittable=false`，导致重排时整项不可缩短）。修法是把写入收敛成一个函数，而不是砍掉入口。

## 2. Q5 实施细则（授权改动）

### 2.1 `src/lib/constants.ts`

```ts
/** H4 参考口径：某日净时长 ≥ 当日有效预算 × 该比例 记为「达标日」。**不参与晋级判定**。 */
export const GATE_H4_MIN_RATIO = 0.6;

/** H4 分母下限：当日有效预算 < 该值的日期（应急日/休息日）不计入分母，避免「5 分钟也算一天」。 */
export const GATE_H4_MIN_BUDGET_MINUTES = 15;

/**
 * @deprecated v2.7 起不参与任何判定。仅用于 Readiness 页「旧规则参考值」的历史对比展示。
 * 保留数值是为了让用户看到「按旧规则我是不达标的」，而不是静默删除痕迹。
 */
export const GATE_H4_LEGACY_MIN_MINUTES = 240;

/** @deprecated 用 GATE_H4_MIN_RATIO；v2.7 起代码中不得再引用。 */
export const GATE_H4_MIN_MINUTES = GATE_H4_LEGACY_MIN_MINUTES;
```

> `GATE_H4_MIN_RATE = 0.8` 保留，作为达标日**占比**的参考线（同样不进判定）。

### 2.2 `src/lib/domain/stageGate.ts`

- `StageGateInput.days` 每项**新增必填** `budgetMinutes: number`（由调用方取 `getEffectiveBudget`）。若不传则该项**不进 H4 分母**并把 `h4.missingBudgetDays` 计数，**不得**默认 0 或默认 60。
- H4 计算改为：

```
eligible = days.filter(d => d.hasPlan && d.budgetMinutes >= GATE_H4_MIN_BUDGET_MINUTES && 在近 30 天窗口内)
qualified = eligible.filter(d => d.netMinutes >= d.budgetMinutes * GATE_H4_MIN_RATIO)
h4.rate = eligible.length === 0 ? null : qualified.length / eligible.length
```

- `h4` 返回值结构：

```ts
h4: {
  /** 相对预算口径的达标率；分母为 0 时为 null（展示 —，不得当 0） */
  rate: number | null;
  qualifiedDays: number;
  eligibleDays: number;
  missingBudgetDays: number;
  /** 旧 240 分钟口径，仅供展示，永不进 verdict */
  legacyRate: number | null;
  /** 恒为 true：表明本项是参考指标 */
  advisory: true;
}
```

- **从 `blockers` / `passed` 的判定逻辑中删除 H4**。H1/H2（人工验收项）与 H3 的语义保持原样，不做任何改动。
- `evaluateStageGate` 的角色就此明确为**「人工验收清单完成度」**；AC-14 的晋级结论由新增的 `computeReadiness()`（五维证据）独家负责。两者不得互相引用对方结论。

### 2.3 测试与文案

- `stageGate.test.ts` 新增（不可删既有用例）：
  1. `daysCompleted=90`、延迟复测证据 0 条 → readiness 结论必须是 `Need more evidence`。
  2. 单次 AI 分数 9.0 → 结论不变（AI 分数不进判定）。
  3. 30 分钟预算用户，20 个达标日（净 20 分钟） → H4 不得产生 blocker。
  4. `eligibleDays=0` → `h4.rate === null`，不得为 `0`。
  5. 预算 <15 分钟的日期不计入分母（`eligibleDays` 不增）。
- `/stages` 与 `/planner/readiness` 文案：H4 区域标题必须是「投入稳定性（参考，不参与判定）」，并并列显示旧口径 `legacyRate`。

## 3. Q6 实施细则（授权改动）

### 3.1 目标态

| 项 | 规则 |
|---|---|
| 写入者 | **唯一**：`appendTaskFromCandidate()`（新增，`src/lib/services/planWrite.ts`） |
| 入口 | **两个**：材料页「确认草案」、`/planner/candidates` 确认 —— 两者都调用同一个写入者 |
| 幂等键 | `TaskProposalItem.planTaskId`（已存在）。非空 = 已落地，写入者**直接拒绝**而不是再写一条 |
| 预算闸门 | 只在写入者内部跑一次（复用 `validateProposalAgainstBudget`），**不允许**调用方预先扣减 |
| 入池过滤 | 候选池查询必须带 `TaskProposalItem.planTaskId === null`，已落地的不再进池 |

### 3.2 `appendTaskFromCandidate()` 必写字段

`stageId / planDate / module / skill / plannedMinutes / sortOrder / track / primarySkill / priority / sourceKind / splittable / minChunkMinutes / planVersion / originalScheduledDate / resourceId / note / candidateId / decisionJson`

- `priority` / `sourceKind` **必须来自候选的裁决结果**，禁止函数内部写死默认值。
- `planVersion` 取 `nextPlanVersion()`，并在同一事务写 `PlanVersion` 审计（与 `generateAdaptivePlanAction` 口径一致）。
- `splittable` 由 `minChunkMinutes` 推导（`plannedMinutes > minChunkMinutes` → `true`）。

### 3.3 回归证明（必须有）

- `confirmTaskProposalAction` 改动后，`materialPack.integration.test.ts` 追加断言：确认后该 `PlanTask` 的 `priority !== 'P1' || sourceKind !== 'CORE' || planVersion !== 1` 中**至少 planVersion 不再是硬编码 1**，且 `candidateId` 非空、`splittable` 与分钟数匹配。

## 5. 执行期硬性禁止（违反即打回）

1. **不得**对任何「技能分钟」求和口径新增第二套分母。`TaskCandidate.estMinutes` 求和**不得**出现在任何统计页面。

8. 所有新纯函数必须**同输入同输出**，权重版本变更必须能通过版本号复算旧结果。

## 6. 数据层冻结条款（对审计 §10.2 的两处修正，已定稿）

审计 §10.2 的 5 张表字段设计**照此实施**，仅以下两处必须按其修正：

### 6.1 `SkillGap` 必须能承载辅助维度，且结构上不可能混入四项分母

审计注释写「仅官方四项，辅助维度不得进这张表」，会导致 Grammar/Vocabulary/Sentence Structure 的缺口**无处安放**（需求 §3.2/§4 要求它们作为辅助维度被追踪，只是不得与四项等权）。改为：

```prisma
model SkillGap {
  // …
  /** LABEL 的语义分层：OFFICIAL = 四项官方能力；AUXILIARY = 语法/词汇/句子结构 */
  dimensionKind  String @default("OFFICIAL")
  /** dimensionKind=OFFICIAL 时取 LISTENING|READING|SPEAKING|WRITING；
      =AUXILIARY 时取 GRAMMAR|VOCABULARY|SENTENCE_STRUCTURE */
  skill          String
  // …
}
```

- **所有**「四技能占比 / 配比分母 / 弱项排序」查询必须显式带 `dimensionKind: 'OFFICIAL'`。
- 辅助维度只允许出现在：候选任务、缺口清单、补测建议。**不得**出现于任何 `allocatedMinutes` 类字段的分母。
- 必须有一个测试：造 1 条 OFFICIAL + 1 条 AUXILIARY 缺口，断言四技能配比合计仍为 100%、且辅助维度分钟不影响四项占比。

### 6.2 `SkillGap` 唯一键去掉 `kind`

审计写的是 `@@unique([snapshotId, skill, subskill, kind])`。**这是错的**：把 `kind` 放进唯一键意味着同一维度可以同时是一条 `GAP` 和一条 `UNCERTAINTY`，双池立刻变成双份计数，AC-6「低置信度必须进 Uncertainty 且不进 ranked」就形同虚设。

改为：

```prisma
@@unique([snapshotId, skill, subskill])   // 一个维度在一次快照里只有一个裁决
```

裁决互斥由 DB 保证，不靠应用层自觉。
