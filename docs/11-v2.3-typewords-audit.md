## 2. 关键数据结构（固定 commit 事实）

```ts
// app/core/types/types.ts
Statistics {
  startDate: number      // 毫秒时间戳
  spend: number          // 毫秒
  total: number          // 本次总词数
  new: number            // 新词
  review: number         // 复习
  wrong: number          // 错误数
  segments?: [number, number][]   // 计时片段（毫秒）
  sessionRole?: 'single' | 'start' | 'middle' | 'end'
  title?: string
}
```

- 统计写入点：`app/core/composables/usePracticePersistence.ts` 的 `flushStatToStore()`，
  按 `segments` 的日期分组；跨天会话拆成 `start`/`middle`/`end` 多条。
- 备份结构（`app/core/hooks/export.ts`）：

```
{ version:5, val:{ setting:{version:23,val:{...}}, dict:{version:4,val:{...}},
                   PracticeSaveWord:{version:2,val:{...}}, PracticeSaveArticle:{version:1,val:{...}} } }
```

- 导出裁剪：`shakeCommonDict()` 对 `!custom && !system` 的词典清空 `words`；
  因此**内置词库备份只含统计，不含词条正文**，这是本次真实导出（CET-4 `words: []`）的直接原因。

## 3. 能力矩阵（OS 可利用程度）

| TypeWords 能力 | 可用数据 | OS 处置 | 结论 |
| --- | --- | --- | --- |
| 单词跟写 / 拼写 / 听写 | 无逐词结果 | 只导入会话汇总（SUMMARY_ONLY） | 可用（汇总级） |
| 自测（认识/不认识/已掌握） | 无逐词导出 | 不进入七维掌握 | 不可用 |
| FSRS 复习 | `fsrsData`（卡片） | 备份里有，但 OS 不解析 | 保留在对方侧 |
| 错词 / 收藏 / 已掌握词典 | `bookList` 系统词典 `words` | 携带词条时按词典名归类 | 部分可用（需用户主动导出） |
| 学习统计 | `statistics[]` | 导入为词汇练习会话 + 学习时长 | 可用 |
| 词库正文 | 仅 `custom:true` 词典保留 `words` | 解析为 `VocabularyItem` | 可用（自定义词库） |
| 词库导入（TypeWords 侧） | 无路由 | OS 导出包需用户手动导入 | 断点，需文档说明 |
| 数据恢复 | 整库覆盖 | OS 只读备份，不回写 | 安全边界 |

## 4. 集成结论

1. **L1 文件交换成立**：真实 ZIP → `data.json` → OS 解析可用；已用真实导出文件验证，
   `parseTypeWordsBackup` 返回版本 5、4 本词典、0 词条，并给出「内置词典被裁剪」提示。
2. **词条导入需区分来源**：只有 `custom:true` 的词典才有 `words`；
   OS 生成的导出包（`buildTypeWordsBackup`）在 TypeWords 侧表现为自定义词典，可被再次导出。
3. **时长口径**：`segments` 优先于 `spend`；跨天拆条；重叠区间由 OS 侧扣除。
4. **禁止整库覆盖**：`setting.vue` 的 `importData()` 会整体替换本地数据；
   OS 不得自动写入对方浏览器，L2 Bridge 默认关闭。
