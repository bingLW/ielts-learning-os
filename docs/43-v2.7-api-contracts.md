# v2.7 接口契约（API Contracts）

> 适用：v2.7 规划内核新增/改造的全部入口。
> 上游契约：`41-v2.7-architecture.md`（数据流、状态机、§6 AI 层）；本文件只做**可调用面**的汇总。
> 本仓**不提供 HTTP/JSON API**：所有写操作是 Next.js Server Actions，所有读操作是只读查询函数（RSC 直接调用）。
> 本文的路径均为仓库相对路径；`ActionResult` 与错误码约定见 `src/lib/types.ts` / `40-v2.7-decisions.md`。

---

## 0. 三条全局约定

| 约定 | 说明 |
| --- | --- |
| 校验先说清 | 每个 Action 的入参在 action 内用 zod `.strict()` 解析；多余字段直接 `VALIDATION`，**不静默丢弃** |
| 失败不抛 | 业务失败返回 `fail(code, message)`；只有真正的编程错误才抛（`weightedScore` 的 NaN 即属此类，必须在写库前炸） |
| 预览零写计划 | `buildPlan` / `previewReplan` 只写**快照元数据**（`PlanningSnapshot` / `SkillGap` / `TaskCandidate` / `TaskPriorityDecision`），**永不写** `PlanTask` / `PlanVersion`。写计划只发生在 confirm 的同一事务里 |

`ActionResult<T>`：

```ts
type ActionResult<T> = { ok: true; data: T } | { ok: false; code: ErrorCode; error: string };
```

### 0.1 错误码（v2.7 实际会返回的）

| code | 何时出现 | 客户端应做什么 |
| --- | --- | --- |
| `VALIDATION` | zod 不过 / 权重和 ≠ 1 / 配比和 ≠ 100 | 展示字段级错误，不重试 |
| `PRECONDITION` | 缺阶段、缺 `PlannerSettings`、快照不存在 | 显示引导（去建阶段 / 去预算页） |
| `NOT_FOUND` | `snapshotId` / `versionId` / `reviewId` 查无 | 刷新列表 |
| `CONFLICT` | 预览令牌不匹配、同令牌重复确认、输入在预览后变化 | 提示「请刷新预览再确认」，**不要**自动重试 |
| `BUDGET_EXCEEDED` | AI 调用日/月预算拦截（`runAiCompletion` 内部） | 计划照常返回，`aiNote` 里说明 |
| `INVALID_OUTPUT` | AI 输出未过 schema | 计划照常返回，`aiMode='failed'` |

## 1. Server Actions（`src/lib/actions/planner.ts`）

### 1.1 计划生成 / 确认

| Action | 输入 schema（`src/lib/schema/planner.ts`） | 返回 | 写库 | 幂等 |
| --- | --- | --- | --- | --- |
| `generatePlanPreviewAction(raw)` | `planPreviewSchema`：`purpose`(`GENERATE`\|`REPLAN`)、`asOfDate`、`horizonDays`、`stageId?`、`planDate?`、`budgetOverrideMinutes?`(0–600)、`allowAi?`、`draftId?` | `BuildPlanPreviewResult` = `BuildPlanResult` + `previewToken` | 快照四表（见 §0） | 每次调用新建快照（`inputHash` 相同则复用，见 `planningSnapshot`） |
| `confirmPlanVersionAction(raw)` | `planConfirmSchema`：预览入参 + `snapshotId` + `previewToken` | `{ version: number; versionId: string; warnings: string[] }` | `PlanTask*` + 1 条 `PlanVersion` | `idempotencyKey = previewToken`；已存在 → `CONFLICT` |

**`previewToken` 契约**：`sha256(['plan', snapshotId, inputHash, budgetOverrideMinutes ?? ''])` 取 24 位。
`budgetOverrideMinutes` 必须入签 —— 它不在快照 `inputHash` 里，但会改变落库分钟数。
`previewTokenOf` 定义见 `src/lib/services/planBuild.ts`。

**`BuildPlanResult` 的可观察字段**（AI 相关只在这一层暴露）：

```ts
{
  snapshotId: string; inputHash: string;
  ruleVersion: string; weightsVersion: string;
  aiMode: 'off' | 'on' | 'failed';
  aiNote: string | null;                    // failed 时必含错误码
  horizonDays: number;
  days: { date; budgetMinutes; isRestDay; tasks: PlannedTaskDraft[] }[];
  tradeoffs: PlanTradeoffs;
  rejectedAiSuggestions: { title; reason; aiCallLogId: string | null }[];
  warnings: string[];
  preview: true;                            // 字面量：编译期区分预览结果
  layerStructure: PlanLayerStructure | null;
  layer: 'DAY' | 'WEEK' | 'MONTH' | 'CYCLE';
}
```

`PlannedTaskDraft.byAi` 的取值公式（全仓唯一赋值点，`src/lib/services/planBuild.ts` `assembleDraft`）：

```
byAi = aiMode==='on' && candidate.isAiSuggested===true && decision.eligibility==='ELIGIBLE' && ai.picks.has(candidateKey)
```

即：**被 AI 挑中** 且 **调度器确实排进了今天** 且 **决策未被拒绝**，三者缺一不可。

### 1.2 手工调整 / 版本

| Action | 输入 | 返回 | 说明 |
| --- | --- | --- | --- |
| `saveDraftAction(raw)` | `planDraftSchema`（同预览入参） | `{ draftId }` | 存草稿，不生成版本 |
| `promoteCandidateAction(raw)` | `candidatePromoteSchema`：`candidateId`、`priority` | `{ ok: true }` | **只改决策优先级**，不写 `PlanTask` |
| `restorePlanVersionAction(raw)` | `versionRestoreSchema`：`versionId` | `{ version; versionId }` | 生成**新版本**，不改写历史行（append-only） |

### 1.3 重排（T08）

| Action | 输入 | 返回 | 说明 |
| --- | --- | --- | --- |
| `previewReplanAction(raw)` | `replanPreviewSchema`：`planDate`、`newBudgetMinutes`(0–600)、`isRestDay?`、`reason?`(≤500)、`lockedTaskIds?`(≤200) | `ReplanPreviewResult`（含 `previewToken`） | dry-run：**零写库**；过载保护四裁决 + 单日上限 |
| `confirmReplanAction(raw)` | `replanConfirmSchema` = 预览入参 + `previewToken` + `idempotencyKey`(≤120) | `{ version; versionId; diff }` | 同一事务写 `PlanVersion(DIFF)`；`idempotencyKey` 重复 → `CONFLICT` |

### 1.4 阶段就绪 / 阶段切换（T09）

| Action | 输入 | 返回 | 写库 |
| --- | --- | --- | --- |
| `reviewReadinessAction(raw)` | `readinessReviewSchema`：`stageId`、`asOfDate` | `{ reviewId; outcome; dimensions }` | 1 条 `StageReadinessReview`（`criteriaJson` 必存五维明细） |
| `confirmStageTransitionAction(raw)` | `stageTransitionSchema`：`reviewId`、`toStageCode`、`reason`(≥全局最小长度)、`confirmedBy`、`note?`(≤2000) | `{ stageId; code }` | 同事务：review 置 `USER_APPROVED_TRANSITION` + `userConfirmed`、旧阶段完成、目标阶段 ACTIVE、`StageTransitionLog` |

> 系统**只建议**，`READY_FOR_REVIEW` 不是切换。`USER_APPROVED_TRANSITION` 只能由用户确认产生。

### 1.5 周度 / 周期（T13）

| Action | 输入 | 返回 | 说明 |
| --- | --- | --- | --- |
| `acceptWeeklySuggestionAction(raw)` | `weeklySuggestionSchema`：`isoYear`、`isoWeek`、`suggestion{kind,note(≤500),targetMinutes?}` | `{ id }` | 采纳确定性建议；不产生第二套周复盘 |
| `recalibrateCycleAction(raw)` | `cycleRecalibrateSchema`：`asOfDate`、`cycleVersionId?`、`reason`(≥全局最小长度) | `{ cycleId; version }` | 只重算**下一周期**，不改已发生历史 |

## 2. 只读查询（`src/lib/queries/planner.ts`）

所有函数都是**只读**，页面（RSC）直接调用，不经 action。`snapshotId=null` 时取最近一次快照（页面不自行散查）。

| 函数 | 返回 DTO | 关键字段 | 对应页面 |
| --- | --- | --- | --- |
| `getPlannerDashboard(asOfDate?)` | `PlannerDashboardDto` | `banner`、今日决策卡、缺口条、待确认项 | `/planner` |
| `getGapSummary(snapshotId?)` | `GapSummaryDto` | `gaps: GapRowDto[]`、`uncertainties`、`unknowns` | `/planner/evidence` |
| `getCandidateQueue(snapshotId?, filter?)` | `CandidateQueueDto` | `rows: CandidateRowDto[]`（含 `decision.factors/score/eligibility`） | `/planner/candidates` |
| `getExcludedReasons(snapshotId?)` | `ExcludedReasonsDto` | 逐条排除原因（来自 `adaptivePlan.backlog`） | `/planner/candidates` |
| `getBuilderContext(horizonDays, asOfDate?)` | `BuilderContextDto` | `layer`、`stage`、`weights`、`previewReady` | `/planner/build` |
| `getDraft(draftId)` | `DraftDto \| null` | 草稿任务明细 | `/planner/build` |
| `getPlanExplanation(versionId)` | `PlanExplanationDto \| null` | `tasks[].explanation`、`tradeoffs`、`aiDisposition` | `/planner/explain/[versionId]` |
| `getBudgetWeek(weekStart)` | `BudgetWeekDto` | `days: BudgetDayRowDto[]`（`isRestDay`/`isSuggestion`） | `/planner/budget` |
| `getWeeklyTargetSummary(weekStart)` | `WeeklyTargetSummaryDto` | 周目标 vs 每日分配（**不参与实际预算**） | `/planner/budget`、`/weekly` |
| `getReplanContext(planDate)` | `ReplanContextDto` | 当日任务、锁定项、可 DEFER/CARRY 项 | `/planner/replan` |
| `getReadinessView(stageId)` | `ReadinessViewDto \| null` | 五维矩阵、`notConsidered`、阶段门清单 | `/planner/readiness` |
| `getVersionHistory(filter?)` | `VersionHistoryRowDto[]` | `layer`、`staleAt`、`parentVersionId` | `/planner/history` |
| `getVersionDiff(versionId)` | `VersionDiffDto` | 逐行差异（ADDED/REMOVED/KEPT/SHRUNK/CARRIED） | `/planner/history` |
| `getSnapshotProvenanceMap(versionId)` | `SnapshotProvenanceDto` | 版本 → 快照 → 候选/决策的溯源链 | `/planner/history` |

> `CandidateRowDto.decision.eligibility` 的六个取值与中文标签见 `ELIGIBILITY_LABEL_ZH`（`src/lib/constants.ts`）。
> `REJECTED_NOT_IN_POOL` / `REJECTED_AI_OVER_BUDGET` 的行**仍留在候选队列**（可追溯），但不进任何一天的 `tasks`。

## 4. AI 层契约（T14）

3 个 prompt kind 的完整定义（`promptKey` / 版本 / 变量 / schema / 拒绝条件）见 `docs/49-v2.7-prompt-changelog.md`。此处只列调用面：

| 函数（`src/lib/ai/planner.ts`） | 入参 | 成功返回 | 失败返回 | 调用方 |
| --- | --- | --- | --- | --- |
| `planAiAvailable(prisma)` | — | `boolean`（真 = provider 模式为 external） | — | `buildPlan` |
| `polishExplanations({prisma,snapshotId,tasks,timeoutMs?})` | `TaskExplanationSeed[]` | `{ ok:true; polished: Map<key,reason>; callLogId }` | `{ ok:false; code; message; callLogId }` | `applyAiLayer` |
| `suggestCandidateOrder({prisma,snapshotId,pool,budgetMinutes,maxPicks?,dailyBudgets?,timeoutMs?})` | 候选池（≤40 条进 prompt） | `{ ok:true; picks:{candidateKey,why,order}[]; callLogId }` | 同上 | `applyAiLayer` |
| `suggestWeeklyTheme({prisma,snapshotId,metrics,gaps,recentDelta?,timeoutMs?})` | 周指标 + 缺口 | `{ ok:true; options:[{theme,rationale,evidenceRefs}]×3; callLogId }` | 同上 | **当前无调用方**（见 `47` §9） |

三条硬边界：

1. `ai/planner` **不 import** `adaptivePlan` / `allocation` / `replan` / `stageGate` —— AI 不参与调度；
2. 日志 `AICallLog.sessionId/materialId/materialJobId` 恒为 null，`snapshotId` 写入 `redactedMetadataJson`（表结构未改）；
3. 失败一律返回 `{ok:false}`，由 `buildPlan` 回落规则输出；**不抛错、不保留半截效果**。

`aiMode` 状态机（`41 §6.3`）：

| 条件 | 结果 |
| --- | --- |
| `allowAi !== true` 或 provider 非 external | `off`，零次调用，全部 `byAi=false` |
| 任一调用失败（含 `INVALID_OUTPUT` / `BUDGET_EXCEEDED`） | `failed`，**丢弃全部 AI 效果**（已采纳 picks 也不保留），计划照常 `ok:true` |
| 成功且至少采纳 1 条 / 仅润色 | `on`，`aiNote` 记录采纳与润色条数 |
| 成功但全部 pick 被拒 | `on`，`aiNote='AI 建议全部被调度器拒绝'` |
