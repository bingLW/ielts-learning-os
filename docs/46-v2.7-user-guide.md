# v2.7 使用指南（User Guide）

> 这份文档写给**使用者**，不写实现。目标是让你看懂「系统今天为什么这样排」，
> 以及「哪些现象是正常的、哪些才值得怀疑」。
> 算法细节：`44-v2.7-scheduler-spec.md`；已知限制：`47-v2.7-known-limits.md`。

## 1. 你会多出哪些页面

导航里新增 4 个入口（其余页面从页内链接进入）：

| 入口 | 路径 | 什么时候用它 |
| --- | --- | --- |
| **自适应计划** | `/planner` | 每天第一眼：今天做什么、为什么、有没有待确认的计划 |
| **计划构建（7/30/90）** | `/planner/build` | 生成/预览/确认计划；切 7 天 / 30 天 / 90 天视图 |
| **候选队列** | `/planner/candidates` | 系统「考虑过」的所有事：为什么入选、为什么被排除、AI 提了什么 |
| **阶段就绪** | `/planner/readiness` | 这个阶段能不能晋级：五维证据、阶段门清单、切换入口 |

页内可达：

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| 缺口与补测 | `/planner/evidence` | 四技能缺口、辅助维度、证据不足需要补测的项 |
| 计划解释 | `/planner/explain/[versionId]` | 已确认版本的逐任务解释与取舍 |
| 重排 | `/planner/replan` | 预算变了/做不完时，先看 diff 再确认 |
| 预算 | `/planner/budget` | 周预算、档位建议、「这会少排多少」 |
| 历史 | `/planner/history` | 版本时间线、差异、恢复、快照溯源 |
| 周复盘（升级） | `/weekly` | 原有页面 + 周度差量、阈值说明、主题、建议采纳 |

## 2. 先做哪一件：P0–P3 与「为什么」

- **P0 = 今天非做不可**：到期复习、到期复测。P0 **不看分数**，分数只在 P0 内部排先后。
- **P1 / P2 / P3**：其余事情按分数分层，只表示「同等条件下的先后」，不是价值判断。
- 每条任务展开后能看到 **7 个因子**（到期压力、目标相关度、证据支撑、错误重复度、前置条件、时间性价比、偏好匹配）及各自权重。
- **没有数据时会看到中性值，而不是 0**：
  - 没有目标 / 没有在跑的 90 天周期 → 「目标相关度」显示 0.50（中性），不是「你不达标」；
  - 没关联已证实缺口 → 「证据支撑」0.30（中性偏低），不是否定；
  - 从没表达过偏好 → 「偏好匹配」0.50，不是「你不喜欢」。
- 如果某条**从没练过**的维度没有被排上来：那是「没观察到」，不是「确认没问题」。系统会用**补测**去拿证据，而不是靠「错误重复度」抬分。

> 详细判据见 `44` §2.1 与 §2.2。

## 3. 预览 ≠ 已生效

「生成预览」**不会**写任何计划任务，只会留下快照（含候选与评分决策，便于回看）。
只有点「确认」才会真正生成/覆盖计划版本。

- 确认时系统会核对预览令牌：**预览之后数据变了 → 拒绝确认**（提示刷新预览），不会偷偷按新数据落库；
- 同一个预览**重复确认 → 拒绝**（幂等）；
- 换预算再确认 → 也需要重新预览（预算分钟数参与签名）。

## 4. AI 什么时候参与、参与多少

`/planner/build` 有一个「允许 AI 参与」开关（默认关）。AI 只能做两件事：

1. **从候选池里挑顺序**——但调度器会逐条复核；放不下、前置条件不满足、或不在池里的建议会被拒，不会进计划；
2. **润色推荐理由**——只改措辞，不许改分钟数、优先级、到期日。

因此你会看到三种状态（`/planner` 状态带与候选页都会显示）：

| 状态 | 显示 | 你能期待什么 |
| --- | --- | --- |
| AI 未参与 | 灰色徽章「AI 未参与」 | 规则输出，完全可复算；候选页的「AI 建议区」仍然存在，只是写着「AI 未参与本次排序」 |
| AI 已参与 | 「AI 已参与」+ 采纳/润色条数 | 被 AI 挑中**且**确实排进今天的任务，会标「AI 建议」；理由可能被润色 |
| AI 调用失败（已回落规则） | 灰色徽章 + 一行原因（含 `PROVIDER_ERROR` / `TIMEOUT` / `INVALID_OUTPUT` / `BUDGET_EXCEEDED`） | **计划照常可用**：所有任务都是规则产出，`byAi=false`，理由全是模板。不需要你重试，除非你想再试一次 |

几个容易误解的点：

- **被 AI 润色了理由 ≠ 这条是 AI 挑的**。这两个是独立标记；
- **AI 建议被拒会留在「候选队列」**，写清原因（池外 / 超预算 / 前置条件），但**不进今天的任务**；
- **AI 建议超出预算时是整条拒绝，不会按比例裁剪**。系统宁可告诉你「这条今天不做」，也不会给你一条「标题写 60 分钟、实际排 20 分钟」的假任务。

## 5. 空态与降级：看到这些不用慌

| 你看到的 | 含义 | 该做什么 |
| --- | --- | --- |
| `/planner` 只有一张「先做一轮诊断」卡 | 还没有足够的诊断证据，系统不编造缺口 | 去 `/diagnostics` 做一轮初始诊断 |
| 候选队列为空 + 「以下来源读取失败…」提示 | 某些来源表读失败，候选池可能不完整；系统会逐项列出 | 先修数据来源，不要当成「今天没事可做」 |
| 四技能某一行显示「尚未基线」 | 该技能没有可信起点，系统**不假定 0 分** | 用「一键排基线」补测 |
| 阶段就绪页大量「需更多证据（INSUFFICIENT）」 | 证据不足，尤其「覆盖比例」往往是未知 | 正常现象，继续积累证据；不要把这个当「失败」 |
| 周复盘主题是确定性建议、没有 AI 选项 | 周主题 AI 接口尚未接到页面（见 `47` §9） | 用现有建议；不影响计划生成 |
| `/planner/explain` 里「预计产出」显示「无法判断」 | 该任务在确认前没有持久化该字段，或来自没有此快照的旧版本 | 新确认计划会保存预计产出并逐字回读；旧记录如实显示未知，不补写、不猜测 |

## 6. 预算与重排

- `/planner/budget` 的「周目标」是**目标**，不是每日预算来源；实际每日预算仍由每日分配决定（两条链不合并）；
- 候选至少积累 3 个有效历史样本后，系统会用净学习分钟校准预计时长；样本不足时保留默认估时，不把未知填成 0。写作 Task 2、短句写作与口语不同题型的默认估时仍未精细区分；
- 预算低于 15 分钟的日期不进阶段就绪的「投入稳定性」分母（H4 只作参考指标，不再否决晋级）；
- 当天做不完 → 去 `/planner/replan`：先看 diff，再确认。**不做「部分完成」的自动折半**，要么按新预算重排，要么保留原样。

---

## 7. 历史与恢复

- `/planner/history` 里每个版本都挂着**生成它的快照**（候选与决策），可以回溯「当时凭什么这么排」；
- 「恢复」历史版本 = **生成一个新版本**，不改写历史行；
- `MONTH` / `CYCLE` 层版本当前**不支持恢复**（见 `47` §9），只能恢复到 `DAY` / `WEEK`。

## 8. 隐私与数据

- AI 开关关闭时**零外部请求**；
- 开启后只发送候选摘要、缺口摘要、周指标这类结构化文本，**不发送**音频、原始上传文档全文或 API Key；
- 数据都在本机 `prisma/dev.db`；升级前先备份，步骤见 `48-v2.7-migration-guide.md`。
