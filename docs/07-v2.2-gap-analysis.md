> 基线：v2.1（已上线、正在使用）。盘点日期 2026-11-19。
> 原则：不推倒重建、不换技术栈、不删除 v2.1 历史数据；全部变更只做加法。

### 1.4 v2.1 关键不变量（v2.2 必须继续遵守）

1. 净时长唯一来源 `StudySessionDaySplit`；`EnglishMediatedSession.durationMinutes` 不参与求和。
2. 一条时长只落一条 `StudySession`；轨道/技能是属性快照，不重复计时。
3. 复习调度唯一表 `ReviewTask`（四种 targetType 共用）；`EgiuReview` append-only。
4. 阶段升级只给建议，手动切换必须写 `StageTransitionLog`。
5. 完成率分母剔除 `CANCELLED / DEFERRED`；计划时长同口径剔除。
6. 内部数值禁用浮点近似比较；正确率唯一入口 `weightedAccuracy`。
7. 代码中不得出现资源名字面量（资源来自 seed/用户录入）。

## 4. 数据库变更（全部加法）

新建 11 表：`EvidenceRecord`、`SkillProfile`、`BarrierDiagnosis`、`InterventionPlan`、`RetestSchedule`、`LearningCycle`、`WeeklyFocus`、`AIUsageRecord`、`ResourceReference`、`ResourceReadingLog`、（证据附件复用不新建）。

扩展 1 表：`EvidenceAttachment` +4 字段（默认值安全，旧行为不变）。

关系：
- `EvidenceRecord.parentEvidenceId` 自关联（版本链，应用层禁止环）。
- `EvidenceRecord.artifactId → EvidenceAttachment`；`taskId → PlanTask`；`sessionId → StudySession`；`mediatedId → EnglishMediatedSession`（均可空，`onDelete: SetNull`）。
- `RetestSchedule.parentEvidenceId → EvidenceRecord`、`completedEvidenceId`、`planTaskId → PlanTask`；`idempotencyKey @unique`。
- `LearningCycle` ↔ `WeeklyFocus`（Cascade）、`BarrierDiagnosis`（SetNull）。
- 全部新增表带 `createdAt`；可变表带 `updatedAt`；软删除用 `archivedAt`（沿用现状）。

不动任何既有列、不删任何行、不改既有默认值。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 证据表膨胀拖慢页面 | 列表默认 `take` 分页 + 按 skill/type 过滤；详情走 `/evidence?focus=id` |
| 记录负担过高违背 v2.2 §12 | 按预算档位默认记录级别：15 应急不强制；30–60 默认 Quick；60–120 建议 Standard；180+ 可选 Full |
| 迁移破坏 v2.1 数据 | 迁移前 `scripts/backup.sh` 备份 → 副本演练 → 前后行数/FK 校验 → 失败则 `scripts/restore.sh` 回滚 |
| SQLite 无原生 enum | 与现状一致：字符串 + constants 元组 + zod 约束 |
| A4 辅助被误计为独立产出 | 领域函数 `countsAsIndependent()` 强制返回 false；UI 红色标记；测试钉死 |
| 四项平均生成 CEFR | 代码层不提供平均函数；画像页只分项展示；测试断言不存在聚合等级 |
| 技能复测与知识复习串状态 | 两套表（`RetestSchedule` vs `ReviewTask`），不同页面分开展示 |
| Prisma 升 7 风险 | 锁定 6.16.2，不升级 |

## 9. 迁移、备份与回滚方案

1. **备份**：`bash scripts/backup.sh` 生成 `backups/dev-<时间>.db`（迁移前强制）。
2. **演练**：复制 `prisma/dev.db` → `/tmp` 副本；在副本上执行 `scripts/migrations/v2.2.mjs --db <副本>`。
3. **迁移方式**：版本化脚本 + `AppMigration` 版本表（新表）：
   - 由 `prisma migrate diff` 生成 DDL 作为参考，脚本内用 `CREATE TABLE IF NOT EXISTS` / 幂等 `ALTER TABLE` 守卫；
   - 事务内执行；成功后写 `AppMigration(version='v2.2', checksum, appliedAt)`；
   - 老库升级走脚本；全新安装仍用 `db push` + `db seed`（schema.prisma 为唯一真源）。
4. **校验**：迁移前后各表行数快照、`PRAGMA foreign_key_check`、v2.1 关键关联查询（PlanTask↔Stage/Resource、Session↔Task↔DaySplit）。
5. **回滚**：首选 `scripts/restore.sh` 恢复迁移前备份（文档化命令）；向前修复用幂等迁移脚本重跑。

## 11. 结论

v2.2 是**纯加法升级**：不动既有 29 张表的结构与数据，新增证据域 11 张表、6 个页面、2 处既有页面增强。主要风险集中在「迁移完整性」与「记录负担」，均已给出可执行对策。可以进入 Phase 1。
