## 2. 已实施修复

### 2.1 阶段就绪度与覆盖率

- readiness 规则版本升级为 `v2.7.1-readiness-1`。
- D1 分母来自当前阶段诊断蓝图必测子维度，不从已有记录反推。
- 有效 Attempt、Evidence、RetestSchedule 按来源、完成状态、辅助级别和到期条件装配；技术失败、中止、无评分依据样本不进入覆盖分子。
- 未知覆盖率保留 `null`；只有分母已知且完成数为 0 时才显示 0%。
- D1–D5 展示分子/分母、缺失维度、Evidence IDs、无效原因、计算时间、快照 ID 与规则版本。
- READY 只允许人工评审建议；阶段确认另需用户确认，不自动切换。

主要文件：`src/lib/domain/readiness.ts`、`src/lib/services/readiness.ts`、`src/lib/actions/planner.ts`、`src/components/planner/readiness/ReadinessBody.tsx`。

### 2.2 Carryover 与统一计划确认

- 日/周 GENERATE 预览生成 PROMOTE / DEMOTE / BACKLOG / ABANDON 四类裁决，预览不写 `PlanTask` / `PlanVersion`。
- 确认时先校验预览库存和令牌，再在同一事务内应用 carryover、预算装箱、写任务和版本头。
- 令牌纳入逾期任务指纹、预算覆盖、库存、草案和诊断提案指纹；来源变化返回 `CONFLICT`。
- P2002 / P2028 转为可理解冲突；重复确认不重复写任务或增加移动次数。
- 已滚入任务在 replan 中锁定；BACKLOG 不自动变成当天任务；ABANDON 保留审计行，不物理删除。
- 材料草案、手工任务、复测加入计划统一经过计划写入者与预算闸门。
- 旧固定生成、旧自适应生成和旧 `replanDailyTasksAction` 均拒绝写入，避免绕过统一 Planner。

主要文件：`src/lib/services/planBuild.ts`、`src/lib/services/carryoverApply.ts`、`src/lib/services/replanPreview.ts`、`src/lib/services/planWrite.ts`、`src/lib/actions/planner.ts`、`src/lib/actions/replan.ts`。

### 2.3 预算与分钟口径

- `resolveEffectiveBudget()` 作为唯一预算真值，不恢复固定 240 分钟最低要求。
- 无配置行时逐日与批量预算逐字段一致；用户设定值和系统建议值通过 `isSuggestion` 区分。
- 计划分钟：有效状态 `PlanTask.plannedMinutes` 之和，排除 `CANCELLED` / `DEFERRED`。
- 预算占用分钟：`DONE` / `PARTIAL` 取 `max(0, actualMinutes)`；其他有效状态取 `max(actualMinutes, plannedMinutes)`。
- 实际净分钟只来自 `StudySessionDaySplit.minutes`；计时累计秒数不直接充当净学习分钟。

### 2.4 诊断、报告与计划激活

- 诊断原始答案 append-only；技术失败标 `INVALID`，不污染画像。
- 同基线报告取代与 finalize 事务化，失败不覆盖此前报告。
- AI 调用审计字段持久化模型、Prompt 版本和调用日志引用；AI 评估仍标为辅助评估，不作为正式 CEFR/IELTS 成绩。
- 诊断 `PlanProposal` 保持 `DRAFT`，进入 Planner 预览并再次确认后才写正式任务和版本。
- 当前边界：无诊断时 DAY/WEEK 仍可走通用模板；MONTH/CYCLE 被阻断。该边界使 P0-4 保持 PARTIAL。

### 2.5 估时与解释

- 生产候选估时接入近 90 天完成、非异常且净分钟大于 0 的历史样本。
- 至少 3 个样本时使用中位点估计与 P25–P75 区间；同一候选身份样本优先于技能样本。
- 模型版本 `estimate-range-v2.7.1`、规则版本、样本数、校准键和区间写入决策快照；新增样本不回写旧快照。
- 用户指定分钟和诊断提案估时不被历史校准覆盖。
- 计划解释优先回读 `PlanTask.decisionJson`，缺失时回退决策行，二者都没有就显示未记录；不重新评分伪造历史理由。
- Expected Output、目标参照、证据引用和 carryover 摘要按确认时快照保存。

P1-1 仍为 PARTIAL：默认区间仍是通用 80%–130%，写作 Task 2 与短句、口语整段模考与短回答尚未使用不同的权威默认估时。

### 2.6 时区、资产与备份

- 用户可配置 IANA 时区，默认建议 `Asia/Singapore`；业务日期统一走时区服务，覆盖跨午夜、周边界和 DST 测试。
- 修改时区不静默改写原始时间戳。
- 音频/录音删除采用签名 preview + 事务复核 + tombstone；只允许删除无引用资产，保留子行、证据索引和物理文件。
- 上传路径限制在 uploads 目录，拒绝绝对路径、反斜杠、NUL、符号链接和中间目录符号链接；新文件使用排他创建与 `0600` 权限。
- 备份 bundle 覆盖 SQLite 与 `storage/uploads`，包含 manifest、逐文件 checksum、整体 checksum 和迁移账本校验。
- 恢复默认进入 `/tmp` 新目录；覆盖恢复需双重确认并先保存 DB+uploads 安全网，支持显式回滚。

### 2.7 迁移、安装与测试隔离

- `scripts/migrations/v2.7.1.mjs` 为纯加法：9 列、2 索引，checksum 为 `7cd30baa4974708b6b1d2c3e4d279b45cff71eff1a30e78fceff06a4f58328bb`。
- 迁移只接受显式系统临时目录数据库，拒绝真实 `prisma/dev.db`；迁移前自动 `.backup`，校验 integrity、外键和全表行数。
- `scripts/install-v271.mts` 只接受不存在或空数据库，seed 前后检查学习表为 0，并登记 v2.2–v2.7.1 权威 checksum。
- `createTestDb` 与脚本测试助手从空 schema 创建系统临时库，不再复制真实数据库；Vitest 全局 setup 校验真实库运行前后 SHA-256。

## 4. 真实库事故

真实 `prisma/dev.db` 曾被误执行 `prisma db push`：

- 误操作前 SHA-256：`36622ec6602e86128de5d1f98d6fb90bbebb005672063ffce84bf216e210c747`
- 误操作后 SHA-256：`1b7d888e2b3eeb587e02ed2caa622ddd6eecdf8eff7d1c369d5e45a8386772d9`
- `PRAGMA schema_version`：1 → 131
- 误操作后 integrity：`ok`
- 事故后备份：`backups/dev-20261126-214859.db`
- 旧备份 `backups/dev-20261123-220358.db` 缺后续 schema，不能安全恢复覆盖

没有误操作前完整副本，不能声称逐字节恢复或真实库完全未受影响。当前保护措施是保留事故后快照、禁止对真实库执行写命令，并只使用显式 `/tmp` 隔离库。该事故未关闭前 P0-5 不得标 PASS。
