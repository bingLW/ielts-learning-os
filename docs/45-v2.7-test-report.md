## 4. 夹具与注入方式（为什么这些测试可信）

| 关注点 | 做法 | 为什么不是「看起来绿」 |
| --- | --- | --- |
| 数据库隔离 | `createTestDb([...])` 复制 `dev.db` → 临时文件，逐个 `deleteMany` 声明表；delegate 名写错直接抛错 | 每个测试文件显式声明读集；不会把本机开发库的某一行当成事实 |
| AI 外部调用 | `vi.spyOn(OpenAICompatibleProvider.prototype, 'complete')` 注入假响应 | 不 mock 模块图、不发网络请求；`④` 用 `not.toHaveBeenCalled()` 证明「off 时零调用」 |
| Prompt 依赖 | `ensurePromptRegistry(prisma)` 先落库 prompt 版本 | 不依赖开发库是否已 seed；`PromptVersion` 缺失会直接失败而不是静默走 Mock |
| 非空断言 | 所有「全部为 X」的断言前先断言集合非空（任务数、候选数） | 防止 `[].every()` 恒真造成的假绿 |
| 文本扫描 | ⑪ 直接读 `src/lib/services/planBuild.ts`，正则匹配赋值形态 | 不依赖运行时分支覆盖；`byAi` 若被写出第二处赋值会红 |
