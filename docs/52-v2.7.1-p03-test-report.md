## 真实库误操作事故（必须保留）

一次启动隔离浏览器夹具时，命令中的 `prisma db push` 漏传 `DATABASE_URL`，Prisma 输出显示目标为真实 `prisma/dev.db`，随后误执行了 schema 同步。该操作违反了“不得修改真实用户库”的约束。

可核实状态：

- 误操作前 SHA-256：`36622ec6602e86128de5d1f98d6fb90bbebb005672063ffce84bf216e210c747`。
- 误操作后 SHA-256：`1b7d888e2b3eeb587e02ed2caa622ddd6eecdf8eff7d1c369d5e45a8386772d9`。
- `PRAGMA schema_version`：1 → 131。
- 误操作后 `PRAGMA integrity_check=ok`。
- 误操作后关键行数：`PlanTask=8`、`PlanVersion=1`、`PlanningSnapshot=0`、`EvidenceRecord=0`、`DiagnosticAttempt=0`、`StudyRecord=0`、`AudioAsset=0`、`AppMigration=8`。
- 误操作后已执行只读 `bash scripts/backup.sh`，生成 `backups/dev-20261126-214859.db`；该备份完整性为 `ok`，四张关键表行数与事故后源库一致。
- 旧最近备份 `backups/dev-20261123-220358.db` 的 `schema_version=1`，缺 v2.2–v2.7 后续结构，不能安全恢复覆盖。

结论边界：没有误操作前的完整数据库副本，不能证明逐字节恢复，也不能继续声称真实库“完全未变”。当前保护措施是保留事故后快照、禁止对真实库执行任何写命令，并从此在所有 Prisma 命令上显式绑定 `/tmp` 隔离 `DATABASE_URL`。该事故不计为 P0-5 通过；最终发布判断必须单独披露。

## 结论

P0-3 的代码、自动化与 Chrome 入口验收通过。P0-5 因真实库事故和完整首次使用链路尚未闭环，不据此标记 Ready for First Use。
